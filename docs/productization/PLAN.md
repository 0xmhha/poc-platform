# 구현 계획과 완료 기준

대상은 stable-platform 및 poc-contract의 현재 작업 트리다. 이전 수정과 사용자 변경을 유지한다.

1. TypeScript compiler API, Go go/parser, Solidity compiler AST로 소스·선언·의존·호출 그래프를 생성한다. 해석 불가능한 동적 호출과 제외 범위를 명시하고 기능별 성숙도 목록을 작성한다.
2. PG 결제/승인/취소/부분 환불, 온램프, 오프램프를 공통 결제 도메인으로 모델링한다. 통화 최소 단위 정수, 견적 만료, KYC, 상태 전이, 멱등성, 영속성, 감사·복식 원장, 서명 webhook, 재처리·대사 경로를 구현한다.
3. 시뮬레이터와 사업자 어댑터를 동일 인터페이스로 제공한다. 성공·거절·추가 인증·대기·장애·중복 알림을 결정적으로 재현하고 실제 사업자 교체 시 결제 도메인을 유지한다. 실험실 UI는 시뮬레이션 전용으로 두고 실사업자 hosted 인증 UI와 분리한다. 미확인 결제는 자동 성공으로 처리하지 않는다.
4. 웹 결제 실험실에서 세 흐름과 상태·잔액·이벤트를 실제 서비스에 연결한다. 브라우저에 서비스 비밀을 노출하지 않고 시뮬레이션 표시를 유지한다.
5. API/재시작/중복·동시 요청/실패 보상/webhook/어댑터 계약/웹/전체 회귀 테스트와 실행 문서를 완료한다.

실제 PG 계약·운영 자격·KYC 공급자·정산 계좌는 시뮬레이터로 대체한다. 실제 사업자용 비밀이나 외부 자금 이체를 생성하지 않는다. 운영 출시 인증과 전체 금융 모듈의 외부 감사는 로컬 테스트 통과와 구분한다.
